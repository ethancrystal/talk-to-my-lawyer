## Shipped this run (code)

Prior audits flagged the homepage social/answer-engine card as a real defect but
deferred it. It was code-fixable with **no external asset**, so it's done:

1. **Keyword-rich homepage `og:`/`twitter:` copy.** The served homepage
   `og:title` was the generic, non-keyword **"Talk to My Lawyer – Professional
   Legal Letters"** even though the `<title>` is keyword-optimized. Social shares
   and AI answer engines surface `og:*`, so this wasted the most-shared field on
   a phrase that ranks for nothing. Now aligned to
   **"Attorney-Drafted Legal Letters – Demand & Cease and Desist"** with a
   benefit-led, keyword-rich description (flat fee / no hourly billing / first
   letter free). Fixed in both `server/spaRoutes.ts → PUBLIC_ROUTE_SEO["/"]`
   (the authoritative injected copy) and the static shell `client/index.html`.

2. **Completed the Open Graph set with image alt text.** Added `og:image:alt`
   and `twitter:image:alt` to every route via
   `injectSeoIntoHtml()` (and matching `stripManagedHeadTags` rules so no
   duplicates leak through from the prerender/Helmet layer), plus the static
   shell. Improves accessibility and answer-engine card quality.

Validation: `server/spaRoutes.test.ts` (18/18) green; `pnpm check` clean.

### Deliberately *not* changed (and why)

- **OG image is a 192×192 square logo** with a `summary_large_image` card (wants
  ~1200×630). Still the single best social/CTR upgrade, but it **needs a design
  asset** — not safe to auto-generate brand imagery unattended. When an asset
  exists, set it as `DEFAULT_IMAGE` in `server/spaRoutes.ts` and the static tags
  in `client/index.html` (and consider per-service OG art).
- **`Organization` `sameAs`** — still absent; needs the real social/Karish
  profile URLs to be worth shipping.
- **LCP `fetchPriority` hint (prior M4)** — the homepage hero is text (the `<h1>`
  is the likely LCP element, no hero `<img>`), so there is no above-the-fold
  image worth prioritizing. No-op here; skipped.
