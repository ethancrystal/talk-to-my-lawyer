## 1. What's working well (keep doing this)

The repo's on-page SEO is genuinely strong. Verified present:

- **Per-page dynamic meta** via `react-helmet-async` *and* server-side injection (`server/spaRoutes.ts → injectSeoIntoHtml`) — unique `<title>`, meta description, and **self-referencing canonical** on every public route (`/`, `/pricing`, `/faq`, `/terms`, `/privacy`, `/blog`, `/blog/:slug`, `/services`, `/services/:slug`).
- **Server-side prerendering** (`server/_core/vite.ts`) with a **fallback HTML** path (`spaRoutes.ts`) so JS-blind crawlers still receive content — this correctly solves the usual "SPA = soft 404" trap.
- **Rich structured data:** `WebSite` + `LegalService`/`Organization` in the static shell (`client/index.html`), plus per-page `Article`, `FAQPage`, `BreadcrumbList`, `Service`/`OfferCatalog`, and `ItemList`. FAQ schema is auto-extracted from blog H2s — good for AI answer engines and rich results.
- **Dynamic `sitemap.xml`** (`server/sitemapRoute.ts`) covering static pages, all `/services/{slug}`, and every published blog post with per-row `<lastmod>`.
- **Smart intended robots policy** (`client/public/robots.txt`): blocks training-only AI crawlers (`GPTBot`, `Google-Extended`, `CCBot`, `Bytespider`, `anthropic-ai`) while *allowing* search + AI answer/retrieval bots (`Googlebot`, `Bingbot`, `PerplexityBot`, `ClaudeBot`, `OAI-SearchBot`, `Amazonbot`, …) and closing app/API surfaces.
- **`X-Robots-Tag` HTTP header** mirrors meta-robots, and `llms.txt` is published for AI agents.
- **Bing Webmaster verified** (`msvalidate.01` + `BingSiteAuth.xml`), California geo-meta, OG image absolute URLs.
- **Perf hygiene:** Vite manual vendor chunking, `preconnect`/`dns-prefetch` for fonts, `font-display=swap`, lazy/eager `loading` + explicit `width`/`height` on logos (CLS guard).

This is an A-grade on-page foundation. The problems below are about whether any of it is **reaching crawlers**.

## 2. Critical findings (these are why we're invisible)

### 🔴 CRITICAL #1 — The served `robots.txt` is Cloudflare-managed and overrides ours

The robots.txt actually served at `https://talk-to-my-lawyer.com/robots.txt` is **not** `client/public/robots.txt`. It is a Cloudflare "Managed robots.txt" / AI-bot-blocking block:

```
# BEGIN Cloudflare Managed content
User-agent: *
Content-Signal: search=yes,ai-train=no
Allow: /
User-agent: Amazonbot      Disallow: /
User-agent: ClaudeBot      Disallow: /
User-agent: CloudflareBrowserRenderingCrawler  Disallow: /
User-agent: GPTBot         Disallow: /
User-agent: Google-Extended Disallow: /
User-agent: meta-externalagent Disallow: /
... (CCBot, Bytespider, Applebot-Extended, etc.)
# END Cloudflare Managed Content
```

**Consequences:**
1. **No `Sitemap:` directive is served.** Our repo robots.txt ends with `Sitemap: https://www.talk-to-my-lawyer.com/sitemap.xml`, but the Cloudflare-managed version drops it — so search engines lose the primary sitemap-discovery signal.
2. **It blocks bots we intentionally allow.** `ClaudeBot` and `Amazonbot` are *allowed* in our policy (they power AI answer engines = visibility) but are *disallowed* at the edge. Our deliberate "search=yes, allow answer engines" strategy is being silently reversed.
3. **Our granular `Disallow:` rules are gone** (`/admin`, `/dashboard`, `/login`, `/api/`, …). Private surfaces now rely *only* on meta-robots / `X-Robots-Tag` rather than defense-in-depth.

**Fix (Cloudflare dashboard — not a code change):**
- Cloudflare → the zone → **Settings / Scrape Shield / AI Audit → "Manage robots.txt"** (a.k.a. *Block AI bots* / *Managed robots.txt*). **Turn it off**, or switch it to "Append" so it does not replace our file. Then re-verify that `/robots.txt` serves the repo version *with* the `Sitemap:` line.
- Confirm **Bot Fight Mode / Super Bot Fight Mode** is not challenging `Googlebot`/`Bingbot` (see #2).

### 🔴 CRITICAL #2 — `sitemap.xml`, `/`, and `/pricing` return 404 to external crawlers

Every external fetch of `https://talk-to-my-lawyer.com/` , `/pricing`, and `/sitemap.xml` returned **HTTP 404**, while `/robots.txt` (a Cloudflare-served static file) returned 200.

This pattern is consistent with **Cloudflare bot management returning 404/blocks to non-allowlisted automated user-agents** (the managed robots block also disallows `CloudflareBrowserRenderingCrawler`). It does **not** prove the site is down for human users or for Googlebot — but it is a strong smell that automated/headless agents are being blocked, and **`sitemap.xml` not being externally reachable is a real indexing problem** regardless of cause.

**Action — verify directly (highest priority):**
1. In **Google Search Console**, use **URL Inspection → Test Live URL** on `/`, `/pricing`, `/blog`, and a service page. Confirm Googlebot gets `200` + rendered content (not a soft-404 / blocked render).
2. **Submit `sitemap.xml` in GSC** and confirm it's *Read successfully* with the expected URL count. If GSC can't fetch it, the edge is blocking it.
3. Check Cloudflare **Security → Events** for blocked `Googlebot`/`Bingbot`/sitemap requests. Allowlist verified search-engine bots if Bot Fight Mode is interfering.
4. Confirm the `/sitemap.xml` Express route (`server/sitemapRoute.ts`) is actually reachable through Cloudflare (not shadowed by a cache rule or a Pages/Workers route returning 404).

### 🔴 CRITICAL #3 — Essentially zero organic visibility / authority

A Google search for the literal domain **`talk-to-my-lawyer.com`** returns **nothing about the actual site** — only generic "how to talk to a lawyer" articles. A search for our core positioning (**attorney-drafted demand letters, flat fee**) surfaces competitors — `terms.law` ($575 flat fee), `justicedirect.com`, `letterdash.com` ($199), `jdwoodslaw.com` — but **not us**.

This means the domain is, for practical purposes, **not yet ranking** for brand or money terms. Causes are some combination of: a young domain, **no/low backlink authority**, the crawl/indexing blockers in #1–#2, and thin published content. The on-page work can't convert to traffic until the domain is crawlable *and* has authority.

**Action — this is a program, not a one-off:**
- **Backlinks/authority:** get listed on legal directories (Avvo, Justia, FindLaw, Clio, Nolo), the Karish Law Firm site (link `karishlawfirm.com → talk-to-my-lawyer.com`), relevant legal/startup press, and partner sites. This is the single biggest lever for ranking against the incumbents above.
- **Content depth:** the blog system is excellent but underused. Target long-tail money queries the competitors rank for ("how to write a demand letter for unpaid invoice", "cease and desist letter for harassment cost", "security deposit demand letter California"). Each is a `/blog/{slug}` with `Article` + `FAQPage` schema already wired.
- **Programmatic service × jurisdiction pages:** we have 10 service slugs and a California focus. "Demand letter California", "cease and desist California" etc. are winnable long-tail terms.
